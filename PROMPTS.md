# Промпты для реализации задачи

Ниже — промпты, которые использовались для анализа, проектирования и реализации
страницы «Управление расписанием». Задача выполнялась по OpenSpec (spec-driven development):
сначала планирование, затем реализация по `tasks.md`, затем проверки и поставка.

## 1. Исходный промпт

```text
Изучи проект clinic-service и tasks/task1.md. Выяви пробелы в описании задачи,
задай вопросы по неоднозначным местам и согласуй детали перед реализацией.

Нужно добавить страницу «Управление расписанием» с формой: поликлиника, врач выбранной
поликлиники, дата, начало и окончание рабочего интервала, необязательный перерыв.

Требования:
- запись делится на получасовые слоты; интервал 09:00–11:00 без перерыва даёт 4 слота;
- созданные слоты появляются в существующем расписании и доступны для записи;
- у врача не должно быть пересекающихся интервалов;
- существующие слоты и записи пациентов сохраняются;
- ошибка формы должна объяснять проблему.

Дополнительно: подключи OpenSpec и реализуй фичу по SDD-фреймворку.
Результат: PR на GitHub, промпты и скриншоты сайта с доработкой.
```

## 2. Уточняющие промпты

```text
Предложи, как обрабатывать время, не кратное 30 минутам: отклонять ввод или создавать
только полные слоты. Какие ещё пограничные случаи нужно согласовать?

Как поступать, если в выбранном интервале уже есть слоты врача: отклонять весь запрос,
пропускать занятые слоты или показывать частичный результат?

Можно ли выбирать сегодняшнюю дату? Что делать с уже прошедшими слотами?

Должен ли перерыв находиться строго внутри интервала? Можно ли указать только начало
или только окончание перерыва?

Нужна ли отдельная таблица рабочих интервалов и перерывов, или достаточно создавать
только слоты? Требуется ли миграция существующей базы?

Нужен ли JSON API с теми же правилами, что и HTML-форма? Какие коды ответов использовать
для конфликтов и ошибок валидации?
```

Принятые ответы зафиксированы в `openspec/changes/add-schedule-management/design.md`.

## 3. Промпт для OpenSpec-предложения

```text
Подключи OpenSpec к проекту, не меняя стек приложения. Создай изменение
add-schedule-management по схеме spec-driven. Подготовь proposal.md, delta-спецификацию
в specs/doctor-schedule-management/spec.md, design.md и tasks.md. Артефакты — на русском,
структурные заголовки и SHALL/MUST — на английском. Проверь изменение командой
openspec validate --strict.
```

## 4. Промпт для модели и валидации

```text
Добавь в app/models.py модель ScheduleCreate и результат ScheduleCreation. Общая
валидация должна использоваться и HTML-формой, и API:
- дата не в прошлом;
- границы интервала и перерыва кратны 30 минутам;
- окончание позже начала, интервал не короче 30 минут;
- перерыв необязателен, но если указан — нужны оба поля, окончание позже начала,
  перерыв строго внутри интервала и оставляет слоты до и после него;
- лишние поля запрещены.

Добавь тесты на корректные и ошибочные данные, включая невыровненное время,
неполный перерыв и дату в прошлом.
```

## 5. Промпт для репозитория и транзакции

```text
Реализуй ClinicRepository.create_schedule:
- в одной транзакции BEGIN IMMEDIATE проверь поликлинику, врача и его принадлежность
  выбранной поликлинике;
- найди существующие слоты врача, пересекающиеся с интервалом по правилу
  starts_at < конец AND ends_at > начало;
- при конфликте отклони весь запрос и верни список конфликтующих слотов;
- отдельно проверь пересечение перерыва с существующими слотами;
- создавай слоты по 30 минут, исключая перерыв;
- для сегодняшней даты создавай только будущие слоты и считай пропущенные;
- если будущих слотов не осталось — верни понятную ошибку;
- существующие слоты, записи пациентов и их статусы не изменяй;
- обеспечь защиту от одновременного создания одинакового интервала.

Добавь тесты репозитория на все эти случаи, включая конкурентные запросы.
```

## 6. Промпт для API и HTML

```text
Добавь POST /api/schedule с теми же правилами, что и HTML-форма. Успех — 201, Location
на расписание, created slots и skipped_past. Конфликт — 409 с detail и conflicts.
Отсутствующая поликлиника или врач — 404. Невалидный ввод — 422.

Добавь страницу GET/POST /schedule/manage без JavaScript. Форма должна:
- показывать только врачей выбранной поликлиники;
- сохранять введённые значения при ошибке;
- показывать ошибки по полям и общее объяснение;
- при конфликте оставаться на форме и показывать конфликтующие слоты;
- после успеха перенаправлять в расписание с сообщением о созданных и пропущенных слотах.

Добавь ссылку с расписания и пункт меню, стили и тесты HTML/API.
```

## 7. Промпт для проверки и поставки

```text
Обнови README: новая страница, правила создания расписания, POST /api/schedule,
сохранение данных и отсутствие миграции.

Запусти в виртуальном окружении:
python -m pytest
python -m ruff check .
python -m ruff format --check .

Запусти приложение с --demo, создай свободный интервал через страницу, проверь появление
слотов в расписании, сделай скриншоты формы, результата и конфликта. Создай ветку,
закоммить изменения, отправь в origin и открой PR с описанием, промптами и скриншотами.
```
