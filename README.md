# Поликлиника

Учебная информационная система сети из 5 поликлиник: расписание врачей, запись на приём,
карточки пациентов и результаты лабораторных исследований. Все демонстрационные данные вымышлены.

**Стек:** Python 3.11+, FastAPI, SQLite, Jinja2, Uvicorn. Обычные HTML-формы и CSS,
без сборки фронтенда. Для работы достаточно Python и браузера; отдельный сервер базы не нужен.
Рекомендуем Python 3.13. Локальные проверки выполнены на Python 3.13.

## Быстрый запуск

Откройте терминал **в папке `clinic-service`**, где находится этот README.
Интернет нужен для первоначальной установки зависимостей.

### macOS / Linux

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m app --demo
```

### Windows (PowerShell)

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m app --demo
```

Если команды `py` нет, попробуйте `python`. Активация окружения не требуется:
команды явно вызывают Python из `.venv`. На некоторых дистрибутивах Linux компонент
`venv` устанавливается отдельно средствами системы.

Откройте **http://127.0.0.1:8000**. Остановка сервера — `Ctrl+C`.
Если порт занят, запустите `.venv/bin/python -m app --demo --port 8001`.

Последующие запуски: `.venv/bin/python -m app`.
На Windows в остальных командах заменяйте `.venv/bin/python` на `.venv\Scripts\python.exe`.
Для запуска без инструментов разработки можно установить только `requirements.txt`.

## Что работает

- Расписание по поликлинике и дате, по умолчанию на завтра.
- Управление расписанием: регистратор добавляет врачу рабочий интервал на выбранную дату,
  и система создаёт получасовые слоты с необязательным перерывом.
- Создание пациента: ФИО, дата рождения и необязательный телефон.
- Запись пациента на свободный слот.
- Журнал приёмов и отдельная карточка каждой записи.
- Отмена записи с освобождением времени и сохранением истории.
- Завершение начавшегося приёма с текстовой заметкой.
- Медицинская карта: данные пациента, приёмы во всей сети, заметки и лабораторные результаты.
- JSON API с интерактивной документацией на http://127.0.0.1:8000/docs.

Демонстрационное расписание подготовлено заранее; новые слоты можно добавить на странице
«Управление расписанием». Интерфейса редактирования существующих слотов и справочников,
импорта результатов и подключения к реальной лаборатории нет.

## Демонстрационные данные

Параметр `--demo` наполняет **только полностью пустую базу**:

- 5 поликлиник с адресами;
- по два врача в каждой: терапевт и кардиолог;
- по шесть получасовых слотов на врача в день — вчера, сегодня и на 14 дней вперёд;
- шесть пациентов и шесть приёмов в разных состояниях;
- завершённое посещение с заметкой и три лабораторных результата.

Повторный запуск с `--demo` не дублирует примеры, не сдвигает даты и не меняет ваши данные.
Если база уже содержит хотя бы одного пациента или другой объект, примеры не добавляются.

Два сценария для знакомства:

1. На главной странице выберите свободное время, нажмите «Записать», выберите пациента
   и подтвердите запись. В карточке приёма можно отменить запись.
2. В разделе «Приёмы» откройте вчерашний запланированный приём Белова Михаила Андреевича.
   Введите итоги и завершите его. Заметка появится в медицинской карте пациента.

Карта Александровой Ольги Игоревны уже содержит завершённое посещение и результаты исследований.

## Правила данных

- Один слот может иметь только одну неотменённую запись.
- Пациента нельзя записать на пересекающиеся по времени приёмы, даже в разных поликлиниках.
  Соседние интервалы, например 09:00–09:30 и 09:30–10:00, разрешены.
- Новая запись возможна только до начала приёма. Длительность демонстрационных слотов — 30 минут.
- Запланированный приём можно отменить, в том числе после времени его начала.
  Повторная отмена безопасна. Прошедший слот после отмены остаётся недоступен для новой записи.
- Завершение разрешено только после начала запланированного приёма, с непустой заметкой.
- Завершённые приёмы нельзя отменять или перезаписывать. Отменённые нельзя завершать.
- Дата создания записи не меняется при отмене или завершении.
- ФИО: 1–120 символов. Заметка: 1–4000 символов. Пробелы по краям удаляются.
- Дата рождения не может быть в будущем. Телефон необязателен; если заполнен,
  содержит 7–15 цифр, допускаются `+`, пробелы, скобки и дефисы. Максимальная длина — 30 символов.
- Пациенты с одинаковыми ФИО и датой рождения допускаются: идентификатор карты различает их.
- Все даты и время хранятся в UTC. Дата расписания и отображение времени — фиксированный
  UTC+3 (МСК) для всей учебной сети, независимо от часового пояса компьютера.
- Рабочий интервал и перерыв задаются по сетке 30 минут: минуты `00` или `30`.
  Интервал `09:00–11:00` без перерыва даёт четыре слота. Перерыв необязателен, должен
  находиться строго внутри интервала и не пересекаться с существующими слотами.
- Если в выбранном интервале у врача уже есть слоты, запрос отклоняется целиком:
  существующие слоты и записи пациентов остаются без изменений, а форма показывает конфликты.
  Соседние интервалы разрешены.
- Дата расписания не может быть в прошлом. Для сегодняшней даты создаются только слоты,
  которые ещё не начались; количество пропущенных прошедших слотов показывается после создания.

Проверки выполняются на сервере и для API, и для HTML. Браузер также проверяет обязательные
поля. Успешная отправка HTML-формы возвращает перенаправление 303: обновление страницы
не повторяет изменение данных. Ошибки формы сохраняют введённые значения.

## Где данные

При запуске автоматически создаётся `data/clinic.sqlite3` в папке проекта.
База сохраняется между запусками и исключена из Git. Тесты используют отдельные временные базы.

Для сброса учебных данных остановите сервер и **удалите папку `data`**.
Затем запустите приложение с `--demo`: оно создаст новую базу с пятью поликлиниками
и расписанием относительно текущей даты. Резервные копии для учебного сброса не нужны.

Начальная схема создаётся автоматически; её версия записана в `PRAGMA user_version`.
Миграций между версиями пока нет. При изменении схемы нужно обеспечить обновление
существующей базы: одного изменения `CREATE TABLE IF NOT EXISTS` недостаточно.

## Разработка и проверки

После установки `requirements-dev.txt`:

```sh
.venv/bin/python -m pytest
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
```

Тесты проверяют API и HTML, валидацию, создание расписания и конфликты слотов, отмену
и завершение, сохранение после перезапуска, демонстрационные данные, экранирование HTML,
временные зоны и одновременные попытки записи.
Предупреждения библиотек считаются ошибками. Версии зависимостей зафиксированы.

Автоматическая перезагрузка Python-кода:

```sh
.venv/bin/python -m uvicorn app.main:create_app --factory --reload
```

Режим использует уже созданную базу; примеры сам не добавляет. HTML и CSS достаточно
посмотреть после обновления страницы. В IDE выберите интерпретатор из `.venv`,
модуль запуска `app` и рабочую папку проекта.

## Структура

| Файл | Назначение |
|---|---|
| `app/__main__.py` | Запуск `python -m app`, параметры `--demo` и `--port` |
| `app/main.py` | Фабрика приложения, жизненный цикл, общая обработка ошибок |
| `app/models.py` | Модели, валидация, статусы и часовой пояс |
| `app/errors.py` | Ошибки предметной области |
| `app/repository.py` | Схема SQLite, запросы и атомарные изменения |
| `app/demo.py` | Демонстрационное наполнение |
| `app/api.py` | JSON API |
| `app/web.py` | Страницы и HTML-формы |
| `app/templates/` | HTML-шаблоны |
| `app/static/` | Локальные стили |
| `tests/` | Автоматические проверки |

Сущности: поликлиника, врач, пациент, слот расписания, запись на приём, лабораторный результат.
В этой версии каждый врач закреплён за одной поликлиникой. Медицинская карта собирается
из данных пациента, его приёмов и исследований; отдельной копии истории в базе нет.

Каждая операция открывает и закрывает своё соединение SQLite. Внешние ключи включены.
Бронирование проверяет слот и пересечения пациента в одной транзакции `BEGIN IMMEDIATE`.
Дополнительно уникальный частичный индекс запрещает двойное занятие слота на уровне базы.
Синхронные обработчики выполняются в пуле потоков. Импорт модулей и создание объекта
приложения сами по себе не создают базу: это происходит при старте.

## API

| Метод | Адрес | Действие |
|---|---|---|
| GET | `/api/clinics` | Поликлиники |
| GET | `/api/doctors?clinic_id=1` | Врачи поликлиники |
| GET | `/api/slots?clinic_id=1&date=2026-11-25` | Расписание на дату по МСК |
| POST | `/api/schedule` | Создать слоты врача на выбранный интервал |
| GET | `/api/patients` | Пациенты |
| POST | `/api/patients` | Создать пациента |
| GET | `/api/patients/{id}` | Пациент, его приёмы и исследования |
| GET | `/api/appointments` | Все записи на приём |
| POST | `/api/appointments` | Записать пациента |
| GET | `/api/appointments/{id}` | Карточка приёма |
| POST | `/api/appointments/{id}/cancel` | Отменить запись |
| POST | `/api/appointments/{id}/complete` | Завершить приём с заметкой |

Создание пациента:

```json
{"full_name": "Иванов Иван Иванович", "birth_date": "1990-05-12", "phone": "+7 (900) 000-00-00"}
```

Запись на приём (возьмите свободный `slot_id` из расписания):

```json
{"patient_id": 1, "slot_id": 8}
```

Создание расписания врача (время по МСК, перерыв необязателен):

```json
{
  "clinic_id": 1,
  "doctor_id": 1,
  "date": "2026-12-01",
  "start_time": "09:00",
  "end_time": "12:00",
  "break_start": "10:00",
  "break_end": "10:30"
}
```

Ответ 201 содержит созданные слоты и `skipped_past` — количество прошедших слотов,
пропущенных при создании на сегодня. При конфликте с существующими слотами ответ 409
содержит `detail` и список `conflicts`.

Завершение приёма:

```json
{"note": "Проведён плановый приём. Итоги и рекомендации сохранены."}
```

Создание возвращает 201 и заголовок `Location`. Ошибки данных — 422,
отсутствующая сущность — 404, конфликт с текущим состоянием — 409.
Неизвестные поля в моделях запросов отклоняются.

## Границы версии

Это локальное приложение, которое слушает `127.0.0.1`. Авторизации, ролей, редактирования
и удаления существующих слотов, поиска, переноса записей, отчётов, импорта и аудита
изменений здесь пока нет.
Эти направления доступны для последующего развития сервиса.

Основной интерфейс и API после установки зависимостей работают без сети: нет внешних
шрифтов, CDN и JavaScript. Страница `/docs` загружает Swagger UI из сети.
Используйте только вымышленные данные; публичное размещение и работа с реальными
медицинскими данными потребуют отдельного проектирования.
