# Proposal

## Why

Сейчас расписание врачей подготовлено заранее, и регистратор не может добавить время приёма
через интерфейс. Из-за этого новое расписание приходится вносить в базу вручную, а ошибки
ввода не проверяются. Нужна страница, которая позволяет безопасно дополнить расписание
врача, не затрагивая существующие слоты и записи пациентов.

## What Changes

- Добавляется страница «Управление расписанием» с выбором поликлиники, врача, даты,
  рабочего интервала и необязательного перерыва.
- Рабочий интервал разбивается на полные получасовые слоты; перерыв не создаёт слоты.
- Начало, окончание и границы перерыва должны быть кратны 30 минутам, иначе форма
  отклоняет ввод с понятным сообщением. Частичные слоты не создаются.
- Проверяется, что выбранный врач относится к выбранной поликлинике.
- Новый интервал не может пересекаться с уже существующим расписанием врача, включая
  перерыв ранее добавленного интервала. Соседние интервалы разрешены.
- Добавляется API `POST /api/schedules` с теми же правилами, что и HTML-форма.
- Схема SQLite обновляется до версии 2: появляется таблица рабочих интервалов.
  Существующие слоты, пациенты и записи сохраняются при обновлении базы версии 1.

## Capabilities

### New Capabilities

- `schedule-management`: добавление рабочих интервалов врача, разбиение на получасовые
  слоты, перерыв и запрет пересекающихся интервалов.

### Modified Capabilities

Нет: других спецификаций в проекте пока нет.

## Impact

- `app/models.py`: модель и валидация рабочего интервала.
- `app/repository.py`: схема версии 2, создание интервала и слотов в одной транзакции,
  проверка пересечений.
- `app/web.py`, `app/templates/schedule_manage.html`, `app/templates/base.html`,
  `app/templates/schedule.html`, `app/static/styles.css`: страница управления и переходы.
- `app/api.py`: `POST /api/schedules`.
- `README.md`: правила, API и обновление схемы.
- `tests/test_schedule.py`: проверки модели, репозитория, API, HTML и миграции.
