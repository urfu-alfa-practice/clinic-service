# Proposal

## Why

Регистратор не может самостоятельно добавлять время приёма врачей: расписание создаётся только демонстрационным наполнением. Нужна управляемая HTML-форма, которая создаёт доступные для записи слоты, не изменяет существующие данные и исключает пересекающееся расписание врача.

## What Changes

- Добавить страницу «Управление расписанием» в основную навигацию.
- Использовать одну форму с одним полем поликлиники и размещать постоянные подсказки рядом с соответствующими полями в одной основной колонке, без отдельной правой колонки статического текста.
- Позволить выбрать поликлинику, закреплённого за ней врача и одну дату, задать один рабочий интервал и один необязательный перерыв.
- Создавать из рабочего интервала слоты длительностью 30 минут с исключением времени перерыва.
- Проверять шаг времени, границы интервалов, актуальность даты и времени, принадлежность врача поликлинике и пересечения со всеми существующими слотами врача.
- Применять запрет пересечений только к сохраняемым слотам: пересечения исходных рабочих интервалов сами по себе не проверяются, поэтому новый интервал допустим внутри перерыва прежнего интервала при отсутствии конфликтов слотов.
- Выполнять создание расписания атомарно: при любой ошибке не добавлять ни одного слота.
- После успеха показывать существующее расписание выбранной поликлиники и даты с количеством добавленных слотов; новые слоты доступны для записи пациентов.
- Сохранять корректно введённые значения формы и показывать понятные ошибки при неуспешной отправке.
- Не изменять существующие слоты, записи пациентов и схему базы данных.

В первую версию не входят редактирование и удаление слотов, несколько интервалов или перерывов за отправку, повторяющееся и ночное расписание, авторизация и новый JSON API.

## Capabilities

### New Capabilities

- `schedule-management`: добавление регистратором расписания врача на одну дату с формированием получасовых слотов, проверкой ввода, атомарным сохранением и защитой от пересечений.

### Modified Capabilities

Нет.

## Impact

- Пользовательский интерфейс: навигация, новая страница управления расписанием и уведомление на странице расписания.
- Серверная логика: общие модели и валидация, HTML-маршруты, операции репозитория SQLite.
- Данные: добавляются только новые строки в существующей таблице `slots`; миграция схемы не требуется.
- Тесты: предметные проверки генерации слотов, ошибочного ввода, атомарности, параллельных запросов и HTML-сценария.
- Зависимости и внешние сервисы не добавляются; JSON API не изменяется.
