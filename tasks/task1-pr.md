# Управление расписанием врача

Страница «Управление расписанием» позволяет регистратору добавить рабочий интервал врача,
разбить его на получасовые слоты и сразу записать на них пациентов. Существующие слоты и
записи не меняются.

## Что сделано

- `GET/POST /schedule` — выбор поликлиники, врача этой поликлиники, даты, начала и окончания
  интервала, необязательного перерыва.
- Интервал делится на полные слоты по 30 минут; перерыв слоты не создаёт.
- `POST /api/schedules` — то же самое через JSON, с общей моделью валидации.
- Схема SQLite обновлена до версии 2: таблица `schedule_intervals` хранит интервалы и
  перерывы. База версии 1 обновляется при старте без потери данных.
- Ссылки на управление из расписания и главного меню, таблица слотов выбранной даты.
- Тесты: модель, репозиторий, API, HTML, миграция, конкурентное создание.

## Как проверить

```sh
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app --demo
```

1. Открыть http://127.0.0.1:8000/schedule.
2. Выбрать поликлинику и врача, дату в будущем, интервал 09:00–11:00 без перерыва —
   появится сообщение «Добавлено слотов: 4».
3. Открыть расписание на эту дату: слоты видны и доступны для записи.
4. Повторить с интервалом 09:15–11:00 — форма объяснит, что время должно быть кратно
   30 минутам, и сохранит введённое значение.
5. Повторить с пересекающимся интервалом — форма объяснит пересечение.

## Решения по неоднозначностям

1. **Время не кратно 30 минутам — отклоняем.** Не создаём частичные слоты: иначе
   пользователь не понимает, куда делись 15 минут. Ошибка объясняет правило.
2. **Перерыв — часть рабочего интервала.** Новый интервал нельзя добавить даже внутрь
   перерыва существующего. Для этого хранится `schedule_intervals`, а не только слоты.
3. **Проверяются и интервалы, и слоты.** В базе версии 1 есть слоты без интервалов;
   проверка по слотам сохраняет запрет пересечений и для них.
4. **Соседние интервалы разрешены.** 09:00–11:00 и 11:00–13:00 не пересекаются.
5. **Врач должен относиться к выбранной поликлинике** — иначе конфликт 409.
6. **Время вводится по Москве (UTC+3)**, в базе по-прежнему UTC.
7. **Прошлые даты не запрещены:** слоты создаются, но для записи доступны только будущие.
8. **Миграция идемпотентна:** `CREATE TABLE IF NOT EXISTS` добавляет таблицу,
   `PRAGMA user_version = 2` фиксирует версию; база новее версии 2 не открывается.
