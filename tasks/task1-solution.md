# Задание 1. Решение

## Что сделано

- Добавлена страница `/schedule` «Управление расписанием»: поликлиника, врач выбранной
  поликлиники, дата, начало и окончание рабочего интервала, необязательный перерыв.
- Интервал делится на полные получасовые слоты. Перерыв не создаёт слоты.
- Добавлен API `POST /api/schedules` с теми же правилами.
- Схема SQLite обновлена до версии 2: таблица `schedule_intervals` хранит рабочие
  интервалы и перерывы. База версии 1 обновляется при старте без потери данных.
- Добавлены тесты модели, репозитория, API, HTML и миграции.

## Принятые решения

1. **Некратное 30 минутам время отклоняется.** Не создаём частичные слоты: иначе
   пользователь не понимает, куда делись, например, 15 минут из интервала. Форма и API
   возвращают ошибку с объяснением.
2. **Перерыв — часть рабочего интервала.** Поэтому новый интервал нельзя добавить даже
   внутрь перерыва уже существующего интервала. Для этого хранится `schedule_intervals`,
   а не только слоты.
3. **Проверяются и интервалы, и слоты.** В старых базах есть слоты без интервалов;
   проверка по слотам сохраняет запрет пересечений и для них.
4. **Соседние интервалы разрешены.** 09:00–11:00 и 11:00–13:00 не пересекаются.
5. **Врач должен относиться к выбранной поликлинике.** Иначе возвращается конфликт.
6. **Время вводится по Москве (UTC+3).** В базе по-прежнему хранится UTC.
7. **Прошлые даты не запрещены.** Слоты создаются, но для записи доступны только будущие.
   Это не мешает дополнить историческое расписание.
8. **Обновление схемы идемпотентное.** `CREATE TABLE IF NOT EXISTS` добавляет новую
   таблицу, `PRAGMA user_version = 2` фиксирует версию. База новее версии 2 не открывается.
